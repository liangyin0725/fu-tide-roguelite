# 《符潮残夜》技能路线与战斗信息分层设计

日期：2026-09-30  
分支：`codex/high-detail-generated-pixel-art`

## 1. 目标

本次改动包含两个连续阶段：

1. 为全部 18 个技能增加 Lv.3 二选一路线，使 Lv.4、Lv.5 和 Lv.6 觉醒产生不同机制，而不是只增加数值。
2. 为战斗画面建立危险、核心反馈、氛围三个视觉层级，在保留高亮度与压迫感的同时，保证敌方弹幕、Boss 预警和场景目标始终清晰。

现有数值成长、五格技能栏、六格强化栏、四级强化、匹配强化觉醒、双人轮流升级、内测模式和中英文切换都必须继续工作。

## 2. 范围

### 包含

- 18 个 `SKILL_IDS` 各两条路线，共 36 个路线定义。
- Lv.3 路线选择界面与状态流。
- 路线专属 Lv.4/Lv.5 增幅及 Lv.6 觉醒机制。
- 单人、双人、宝箱替换和内测配置兼容。
- 战斗特效优先级、动态数量预算、伤害数字合并和屏幕边缘威胁提示。
- 复用现有 `effectLevel` 设置作为“特效密度：低／标准／高”。
- 中英文文本、自动化测试、构建和浏览器视觉验证。

### 不包含

- 新增技能栏或强化栏位。
- 改变现有经验曲线、Boss 血量、刷怪速度或基础伤害平衡。
- 重绘新的技能图集；本阶段复用现有生成式像素素材、色彩和几何变化。
- 局外解锁路线；路线每局都可重新选择。
- 允许局中洗点或更换已确定路线。

## 3. 核心体验

玩家获得某技能的第三个等级时，升级结算暂停并出现“道途分化”。两个选项必须改变攻击方式、目标选择、区域行为、防御方式或弹幕互动之一。选定路线后本局锁定，后续升级卡显示路线名称和下一等级的具体机制变化。

技能达到 Lv.6 时，仍需满足原有 `AWAKENING_REQUIREMENTS`。满足条件后触发该路线对应的觉醒；未满足时保持 Lv.6 基础状态，之后获得匹配强化时再触发延迟觉醒。

战斗中，玩家可以快速区分“必须躲避的敌方危险”和“己方造成的华丽反馈”。画面越拥挤，系统越优先合并重复伤害数字、减少氛围残影和重复粒子，但不会降低敌方弹幕、Boss 范围预警、玩家受击提示或场景目标的可见性。

## 5. 状态与数据模型

### 路线定义

新增独立模块 `src/sim/skillPaths.ts`，包含：

- `SkillPathKey = 'a' | 'b'`。
- `SkillPathDefinition`：技能、路线键、中英文名称、描述、Lv.4/Lv.5 文案、路线觉醒名称与摘要。
- `SKILL_PATHS`：要求每个 `SKILL_IDS` 恰好有两个定义。
- `hasSkillPath`、`getSkillPathDefinition`、`requiresSkillPathChoice` 等纯函数。

`Player` 新增：

```ts
skillPaths: Partial<Record<SkillId, SkillPathKey>>
```

`GameState` 新增：

```ts
pendingSkillPath: {
  playerId: 'p1' | 'p2';
  skill: SkillId;
  resumePhase: 'playing' | 'upgrade';
} | null
```

`GamePhase` 新增 `skill-path-choice`。

### 状态流

1. `applyUpgrade` 将技能从 Lv.2 提升到 Lv.3。
2. 若该技能尚无路线，`chooseUpgrade` 写入 `pendingSkillPath` 并切换到 `skill-path-choice`。
3. `chooseSkillPath` 验证玩家、技能、等级和路线后写入 `player.skillPaths`。
4. 系统根据 `resumePhase` 返回升级队列或继续游戏。
5. Lv.4/Lv.5 使用路线定义提供的机制增幅。
6. Lv.6 通过现有觉醒门槛检查，选择路线专属觉醒名称和效果。

路线选择不得重复出现。无路线的 Lv.3+ 状态只允许出现在旧存档迁移、内测配置未完成或测试构造中；进入实战前必须补齐路线。

## 6. 兼容规则

### 匹配强化觉醒

- `AWAKENING_REQUIREMENTS` 继续以技能为键，不因路线改变。
- `isUpgradeAwakened` 需要同时满足：技能 Lv.6、匹配强化已装备、路线已选择。
- 延迟觉醒在后来获得匹配强化时读取当前路线并触发对应觉醒。

### 宝箱替换

- 替换掉技能时，将其等级归零并删除对应 `skillPaths` 项。
- 新技能仍从 Lv.1 开始，在 Lv.3 时正常触发路线选择。
- 强化替换不影响路线。

### 双人模式

- P1 与 P2 各自维护 `skillPaths`。
- 路线选择归属于本次升级的玩家，不改变奇数 P1、偶数 P2 的轮流升级规则。
- 一个玩家选择路线时游戏暂停，另一玩家不能替其选择。
- 双人不得重复装备技能的现有规则保持不变，但相同路线键可以分别用于不同技能。

### 内测模式

- 每个已选且等级不低于 Lv.3 的技能显示 A/B 路线分段按钮。
- 默认选择路线 A，测试者可改为路线 B。
- 启动前校验所有 Lv.3+ 技能已有路线。
- 内测启动后直接按配置重建等级、路线和觉醒状态，不播放 18 次升级动画。

## 7. 机制接入边界

基础等级数值仍由 `applyUpgradeLevelEffects` 统一重建。路线不直接修改永久基础值，而通过以下两类入口接入：

- 静态派生属性：在基础等级重建后由 `applySkillPathLevelEffects` 添加，例如范围、持续时间或额外数量。
- 运行时机制：`GameSimulation` 在对应技能处理函数中调用 `hasSkillPath`，例如二次爆炸、弹幕拦截、移动领域和目标优先级。

每个路线机制必须产生明确的 `CombatEvent`，以便特效、音效、伤害统计和测试使用同一事实来源。不得仅在渲染层伪造机制表现。

## 8. 战斗信息分层

### 三个层级

| 层级 | 内容 | 预算行为 |
| --- | --- | --- |
| `critical` | 敌方弹幕、Boss 危险区、Boss 破势目标、玩家受击、场景目标 | 始终显示；不因特效密度降低亮度或省略 |
| `combat` | 玩家弹道、技能命中、组合技、路线触发、觉醒 | 保留核心轮廓；拥挤时减少重复残影和次级闪光 |
| `ambient` | 火花、余烬、装饰残影、重复冲击纹、非关键漂浮文字 | 根据特效密度限流、合并或提前淡出 |

### 深度规范

新增 `src/render/combatDepths.ts`，集中定义：

- 场景背景与地表装饰。
- 玩家持续领域。
- 玩家弹道与命中特效。
- 敌人本体。
- 敌方弹幕。
- Boss 危险预警与破势目标。
- 屏幕空间威胁指示器和 HUD。

敌方弹幕和 Boss 预警必须高于大面积玩家领域；玩家角色轮廓可以高于己方持续领域，但不得覆盖关键 Boss 标记。

### 动态预算

新增 `EffectBudget`，按渲染帧计算可创建效果数量：

| 特效密度 | `combat` 新效果/帧 | `ambient` 新效果/帧 | 活跃伤害数字上限 |
| --- | ---: | ---: | ---: |
| 低 | 20 | 8 | 20 |
| 标准 | 36 | 16 | 36 |
| 高 | 64 | 28 | 52 |

- `critical` 不参与普通限流；同一危险对象仍只能有一个对应视觉实例。
- 超出 `combat` 预算时优先保留首次命中、击杀、精英/Boss 命中、组合技和路线触发。
- 超出 `ambient` 预算时直接省略最旧或重复装饰，不延迟到后续帧补放。
- 持续技能贴图不重复创建，只更新已有精灵。
- 设置界面将现有 `effectLevel` 文案改为“特效密度”，存储结构与旧设置兼容。

### 伤害数字合并

- `damage-number` 事件补充稳定的目标标识。
- 同一目标、同一伤害来源在 120ms 内的伤害合并为一个数字。
- 合并数字更新总值并重新触发短促放大，不创建新文本对象。
- 玩家受伤、Boss 破势伤害和暴击/觉醒爆发不与普通伤害合并。
- 关闭伤害数字设置时不创建或缓存文本。

### 屏幕边缘威胁提示

- 只提示离屏 Boss、活动场景目标和已进入激活阶段的大型 Boss 危险中心。
- 指示器贴合安全边距，箭头指向世界坐标，显示类型图标和距离。
- 目标进入视口后立即隐藏。
- 普通敌人和普通弹幕不显示边缘箭头，避免噪声。

### 屏幕震动

- 保留现有开关。
- 同一渲染帧只执行最高等级震动。
- 连续震动至少间隔 80ms；觉醒、Boss 转阶段和玩家濒死可突破普通冷却。
- 特效密度不影响震动，震动仍由独立设置控制。

## 9. UI 与本地化

新增“道途分化”全屏选择层：

- 标题显示技能名称与 Lv.3。
- 两张路线卡分别显示核心机制、Lv.4/Lv.5 方向和 Lv.6 觉醒名称。
- 卡片使用技能自身颜色，但危险提示颜色不用于路线装饰。
- 双人模式明确标识 P1/P2。
- 窄屏下两张卡纵向排列，面板可滚动，确认按钮始终可达。

升级卡、技能栏提示、内测面板和觉醒屏幕都显示当前路线名称。所有新增中文必须在 `uiText.ts` 有英文映射；英文模式不得残留路线名称或说明的中文文本。

## 10. 错误处理与迁移

- 当前项目没有局中存档，因此不引入版本化运行存档迁移。
- `createDefaultState` 为所有玩家创建空路线表。
- 旧测试或调试状态中 Lv.3+ 技能缺少路线时，正式开始战斗前自动进入路线补选，而不是静默选择。
- 内测模式缺少路线时禁用开始按钮并标出缺失技能。
- 未知路线键视为无路线，不执行路线机制。
- 路线目录启动测试必须验证 18 个技能完整覆盖且无重复键。

## 11. 测试策略

### 模拟层

- 18 个技能均有且只有两条路线。
- Lv.1/Lv.2 不触发选择，Lv.3 恰好触发一次。
- Lv.4/Lv.5 应用路线专属机制。
- Lv.6 必须同时满足路线和匹配强化才能觉醒。
- 延迟获得强化时触发正确路线觉醒。
- 宝箱替换清除路线。
- P1/P2 路线状态独立，轮流升级顺序不变。
- 每个运行时路线至少有一个行为测试和一个对应事件断言。

### UI 与设置

- 路线选择、升级预览、觉醒名称、内测配置和中英文文本测试。
- 现有 `effectLevel` 低/中/高设置读取旧存储数据并正确控制预算。
- 691×704 窄屏和 1280×720 桌面布局无重叠、无不可达按钮。

### 渲染层

- `critical` 效果在所有密度下均保留。
- `combat` 与 `ambient` 严格遵守预算并按优先级保留。
- 伤害数字按目标与来源合并，活跃数量不超过上限。
- 敌方弹幕与 Boss 危险层深度高于大面积己方领域。
- 屏幕边缘指示器在进出视口时正确显隐。

### 完整验证

- 运行完整 Vitest 测试。
- 运行 TypeScript 检查与 Vite 正式构建。
- 浏览器实际完成一次 Lv.3 路线选择、Lv.6 延迟觉醒、技能替换和双人独立选择。
- 运行至少 20 分钟等价的高密度模拟，确认效果对象、文本对象和映射集合数量受控。
- 在特效密度低、标准、高三档截图比较，确认亮度不明显下降且危险信息始终清晰。

## 12. 实施顺序

1. 建立路线类型、目录完整性测试和玩家状态。
2. 接入 Lv.3 选择状态机、单人/双人恢复流程和 UI。
3. 接入 18 个技能的路线机制、Lv.4/Lv.5 增幅及路线觉醒。
4. 接入宝箱替换、内测配置、升级预览和本地化。
5. 建立深度常量、效果优先级与预算。
6. 实现伤害数字合并、震动节流和边缘威胁提示。
7. 完整自动化测试、构建、真实浏览器与长局压力验证。

## 13. 验收标准

- 18 个技能全部拥有两个可选路线，且路线在 Lv.3 只选择一次。
- 每条路线至少改变一个可观察机制，不能只有伤害、范围或冷却数值差异。
- Lv.6 路线觉醒继续遵守匹配强化门槛。
- 单人、双人、宝箱替换和内测模式状态一致且无卡死。
- 高密度战斗中敌方弹幕、Boss 预警和场景目标不被己方大面积特效遮挡。
- 三档特效密度均保持当前明亮高像素风，高档保持完整华丽表现。
- 后期活跃视觉对象受预算控制，不随事件数量无界增长。
- 所有新增界面支持中英文及窄屏操作。
- 完整测试、正式构建和浏览器验收通过后才可提交完成。
